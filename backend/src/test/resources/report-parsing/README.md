# 自然文解析のテストデータ

## 現在の状態

提供された274件の一次情報を原文のまま収録し、実装した解析器の回帰テストへ接続している。

- `cases.json`: 期待値を定義した274件（登録対象267件、拒否対象7件）。
- `pending-cases.json`: 確認待ちは0件（空配列）。回帰テストと整合性テストの両方で空であることを必須条件とする。
- `ReportParsingFixtureTest`: 件数・ID・データ構造・値の整合性だけを検証する。抽出結果は別の`ReportMessageParserCorpusTest`で全274件を検証する。

人工的な境界条件は`ReportMessageParserTest`と`ReportTagClassifierTest`、保存との接続は`ReportServiceParsingTest`、署名・イベント時刻の受け渡しは`LineControllerTest`で検証する。入力は一次情報の文章だけを対象とする。

## データの扱い

原文は提供資料から複製し、期待値は要件と原文を照合して手作業で定義した。解析器の実行結果から生成したものではない。テストの実行時にローカル資料や計画書を読み込まない。

`sample-001`から`sample-274`のIDは、収録時の原文順に対応する。後から資料の並びが変わっても振り直さない。期待値を修正するときは、実装に合わせるのではなく原文と決定済みの要件を確認する。

全件共通のLINEイベント日時は`japanDateTime`の`2026-10-25T12:00:00+09:00`。発生日時の`occurDate`は日本時間のローカル日時とし、実行日の時計には依存させない。

登録対象の`expected`には日時、都道府県、市区町村、町域・丁目、番地以降、概要、タグをすべて記載する。番地のない場合も`addressDetails: null`を明記する。概要は原文の表記を保持し、段落区切りは半角スペースへ整える。タグの配列順には優先順位の意味を持たせず、解析器との照合では集合として比較する。

拒否対象には`expected`の代わりに`expectedError`を記載する。コードはテストデータ上の識別子であり、エラー型の実装後に対応付ける。

| コード | エラー種別 |
| --- | --- |
| `INVALID_DATETIME` | 日時不正 |
| `UNSUPPORTED_DATETIME` | 未対応の日時形式 |
| `INVALID_ADDRESS` | 住所不正 |
| `INVALID_SUMMARY` | 概要不正 |
| `UNCLASSIFIABLE_TAG` | タグ判定不能 |
| `TOO_MANY_TAGS` | タグ件数超過 |

## 個別事例の確定結果

確認待ちだった39件は合意に基づき確定済み。固有名のない施設・公園・車内も概要へ保持する。名札を引っ張る・日傘を叩く行為は暴行、肩を叩いて声をかける行為は身体接触＋不審な声かけ、脱衣所をのぞき携帯電話を向ける行為はのぞき＋盗撮、相手不明の大声の叫びは追加した大声・奇声とする。

確認待ちを再び追加する場合、期待値を確定するまでは回帰テストが失敗する。未確定ケースのスキップや確定済みケースだけの成功を全件成功として扱わない。
